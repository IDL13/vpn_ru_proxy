# VPN RU Proxy

![VPN RU Proxy logo](chrome-extension/icons/logo-128.png)

VPN RU Proxy направляет выбранные сайты из Chrome через обычное интернет-подключение при включённом VPN. Расширение запускает и останавливает локальный `sing-box` через помощник для macOS, Windows и Linux. Сайты из списка идут через выбранный Wi‑Fi или Ethernet, остальные запросы следуют маршрутам операционной системы.

| Компонент | Адрес или расположение |
| --- | --- |
| Список сайтов | **«Настроить список сайтов»** в расширении |
| Локальный прокси | `127.0.0.1:17892` |
| Расширение Chrome | [`chrome-extension/`](chrome-extension/) |

## Установка

Понадобятся Google Chrome и `sing-box` 1.12 или новее. Установи `sing-box` и проверь его командой `sing-box version`.

| Платформа | Установка sing-box | Имя физического интерфейса |
| --- | --- | --- |
| macOS Apple Silicon | `brew install sing-box` | Имя `Device` из `networksetup -listallhardwareports`, обычно `en0` |
| Windows x64 | `winget install sing-box` | Столбец `Name` из `Get-NetAdapter -Physical` в PowerShell, например `Wi-Fi` или `Ethernet` |
| Linux x64 | Пакет для твоего дистрибутива | Имя из `ip -br link`, например `wlp2s0` или `enp3s0` |

[Установка sing-box по дистрибутивам и платформам](https://sing-box.sagernet.org/installation/package-manager/).

### Подключение обычного Chrome

1. Открой `chrome://extensions` в своём обычном профиле. Включи **«Режим разработчика»** и загрузи папку `chrome-extension` кнопкой **«Загрузить распакованное расширение»** (*Load unpacked*). Если расширение уже загружено из этой папки, нажми кнопку перезагрузки на его карточке.
2. Скопируй ID **VPN RU Proxy** с той же карточки. Выполни команду для своей платформы из таблицы ниже, подставив ID расширения.
3. Открой меню **VPN RU Proxy** и нажми **«Настроить список сайтов»**. Введи имя физического Wi‑Fi или Ethernet-интерфейса из таблицы выше, затем сохрани список сайтов.
4. Нажми **«Включить»** в расширении и обнови нужную вкладку. Кнопка запускает `sing-box` и подключает к нему обычные окна этого профиля Chrome. **«Выключить»** возвращает прежние настройки прокси Chrome и останавливает запущенный экземпляр `sing-box`.

| Платформа | Из папки распакованного архива | Из корня проекта после `cargo build --release --locked` |
| --- | --- | --- |
| macOS или Linux | `./bin/vpn-ru-proxy --install-chrome-host EXTENSION_ID` | `./target/release/vpn-ru-proxy --install-chrome-host EXTENSION_ID` |
| Windows PowerShell | `.\bin\vpn-ru-proxy.exe --install-chrome-host EXTENSION_ID` | `.\target\release\vpn-ru-proxy.exe --install-chrome-host EXTENSION_ID` |

Для сборки нужны [Rust 1.89 или новее и Cargo](https://www.rust-lang.org/tools/install). На Windows установи инструменты MSVC, которые предлагает `rustup`. Если распаковщик на macOS или Linux сбросил права бинарника, выполни `chmod +x ./bin/vpn-ru-proxy`.

Помощник регистрируется для текущего пользователя. На Windows используется `HKCU`. На Linux используется каталог Chrome под `${XDG_CONFIG_HOME:-$HOME/.config}`. Для Chrome с отдельным каталогом данных на macOS или Linux передай его вторым аргументом после `EXTENSION_ID`. [Документация Chrome о регистрации помощников](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging#native-messaging-host-location).

Кнопка **«Включить»** запускает фоновый помощник и sing-box. Он продолжает работу после закрытия меню. Кнопка **«Выключить»** останавливает прокси и завершает помощник. После полного выхода из Chrome прокси нужно снова включить кнопкой.

Настройки можно менять при выключенном прокси. В этом случае Chrome запускает помощник на время чтения, сохранения или импорта списка. Расширение использует тот же `settings.json`, поэтому существующий список подхватится автоматически. Если перенесёшь папку с бинарником или изменится ID расширения, повтори команду установки. [Документация Chrome о загрузке расширения](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked).

### Сборки GitHub Actions

В GitHub открой **Actions → Build desktop packages**. Успешный запуск создаёт ZIP для macOS arm64, Windows x64 и Linux x64. Скачай нужный архив из **Artifacts** или прикрепи его к GitHub Release. `sing-box` устанавливается отдельно.

## Управление списком сайтов

Вводи записи по одной на строку или через запятую и нажимай **«Сохранить список»**. При изменении списка работающий прокси перезапускается с новым конфигом. Это может на короткое время прервать соединения в подключённом Chrome.

| Запись | Что она покрывает |
| --- | --- |
| `example.com` или `*.example.com` | `example.com` и все его поддомены |
| `http://www.example.com/path` или `https://www.example.com/path` | `example.com` и все его поддомены |
| `api.example.com` | `api.example.com` и его поддомены |
| `192.0.2.10` или `2001:db8::10` | Запрос, адресованный напрямую этому IP |

Правила для доменов работают с HTTP и HTTPS. В списке настроек варианты одного домена отображаются одной записью, а правило для поддоменов создаётся автоматически. При ручном редактировании `settings.json` выключи прокси и включи его снова после сохранения файла.

Если включённый VPN мешает разрешать имена из списка, в поле **«DNS для сайтов из списка»** укажи IP-адрес DNS-сервера, доступного через выбранный Wi‑Fi или Ethernet. `sing-box` отправит ему запросы через этот интерфейс. Пустое поле использует локальный DNS, поведение которого зависит от платформы и настроек VPN. [Документация sing-box о локальном DNS](https://sing-box.sagernet.org/configuration/dns/server/local/).

### Импорт `amnezia.json`

В настройках расширения нажми **«Заменить из JSON»**, выбери файл и проверь список в поле. Затем нажми **«Сохранить список»**. Это полностью заменит предыдущий список, включая правила, добавленные вручную. Если хочешь сохранить отдельные ручные правила, добавь их в поле перед сохранением.

Парсер берёт `hostname`, `ip` и все адреса из массива `ips`. Пустые значения пропускаются, повторы удаляются. Ниже показан формат файла с одной записью.

```json
[
  {
    "hostname": "example.com",
    "ip": "192.0.2.10",
    "ips": ["192.0.2.10", "2001:db8::10"]
  }
]
```

## Проверка с включённым VPN

1. Включи VPN и открой [api.ipify.org](https://api.ipify.org) в подключённом Chrome. Убедись, что этот домен пока не покрыт списком. Запомни показанный IPv4.
2. Добавь `api.ipify.org` в список, сохрани список и обнови страницу. Ожидается IPv4 обычного подключения, тот же, который виден без VPN.
3. Удали тестовую запись после проверки. Для отдельной проверки IPv6 можно повторить шаги с [api6.ipify.org](https://api6.ipify.org).

Для проверки маршрутов `sing-box` на macOS отдельно от Chrome запусти тестовый скрипт из корня проекта.

```bash
bash test-sing-box.sh en0
```

Скрипт создаёт временный прокси на `127.0.0.1:17890` и сравнивает обычные запросы с запросами через `sing-box` для IPv4 и IPv6. Параметр `en0` замени на фактический физический интерфейс, если он отличается.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Расширение просит установить помощник | Проверь ID в `chrome://extensions` и повтори команду установки |
| Не удаётся загрузить список | Проверь установку помощника и обнови страницу настроек |
| macOS блокирует запуск бинарника из архива | Используй инструкцию по сборке из исходников |
| Утилита не находит `sing-box` | Выполни `sing-box version`, затем полностью перезапусти Chrome. При ручной установке можно положить `sing-box` или `sing-box.exe` рядом с помощником |
| Linux выдаёт `operation not permitted` при подключении через интерфейс | Для привязки сокета обычным пользователем нужна поддержка `SO_BINDTODEVICE` в ядре Linux 5.7 или новее |
| Chrome показывает `ERR_PROXY_CONNECTION_FAILED` | Проверь состояние `sing-box` в расширении. Нажми **«Выключить»**, чтобы вернуть прежние настройки Chrome |
| Прокси управляет другое расширение или политика Chrome | Проверь, кто управляет настройками прокси в текущем профиле. VPN RU Proxy покажет это в своём меню |
| Ozon сообщает о VPN | Проверь, что в списке есть `ozon.ru` и `ozone.ru`. Сохрани правила и обнови страницу |
| Порт занят | Проверь, какой процесс слушает порт `17892`. Если прокси включён в другом профиле Chrome, выключи его там |

На macOS эти команды показывают слушающие процессы и последние строки журнала.

```bash
lsof -nP -iTCP:17892 -sTCP:LISTEN
tail -n 80 "$HOME/Library/Application Support/vpn-ru-proxy/sing-box.log"
```

В журнале `outbound/direct[without-vpn]` означает, что для запроса выбран физический интерфейс. `outbound/direct[system]` означает обычный маршрут операционной системы. Строка о выборе маршрута сама по себе показывает решение прокси. Чтобы подтвердить внешний IP, используй проверку выше.

## Настройки и совместимость

| Платформа | Каталог настроек и журнала |
| --- | --- |
| macOS | `~/Library/Application Support/vpn-ru-proxy/` |
| Windows | `%LOCALAPPDATA%\vpn-ru-proxy\` |
| Linux | `${XDG_CONFIG_HOME:-$HOME/.config}/vpn-ru-proxy/` |

| Файл или папка | Содержимое |
| --- | --- |
| `settings.json` | Сетевой интерфейс, сохранённый список и необязательный DNS-сервер |
| `sing-box.json` | Конфиг, который генерирует утилита для запуска `sing-box` |
| `sing-box.log` | Журнал текущего запуска прокси |

| Переменная окружения | Назначение |
| --- | --- |
| `SING_BOX_BIN` | Полный путь к `sing-box` в окружении Chrome. Помощник также ищет бинарник в `PATH`, в типовых каталогах установки и рядом с собой |
| `VPN_RU_PROXY_DATA_DIR` | Другой каталог настроек, конфига и журнала |

Прямой выход по IPv4 и IPv6 проверялся на macOS с AmneziaWG. На Windows и Linux проверь внешний IP с включённым VPN по шагам выше. Результат зависит от режима туннеля, сетевых маршрутов и блокировки трафика вне VPN. Happ в режиме системного прокси требует отдельной интеграции.
